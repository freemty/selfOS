# Context Capture: 两种零摩擦模式

> 目标：让"记录自己"这件事的摩擦降到零。不需要写文章、不需要组织语言、不需要打开 Notion。

## 核心问题

你有大量的个人 context（经历、思考、情感、关系、决策），但主动记录的动力不足。当前的记录方式（写 Notion note、和 AI 深度对话）都需要你先有一个明确的意图——"我要记录这个事情"。

真正的解法是：**让 context 在你不刻意记录时也在流入 wiki**。

## 两种 Mode

### Mode 1: Chat（闲聊式）

**触发者：你**
**场景：** 你随便想聊点什么——今天发生了什么、突然的一个想法、看了个有意思的东西、对某人的感受。

**和普通聊天的区别：** Claude 在聊天的同时，默默地做两件事：
1. **匹配**：你说的内容和 wiki 里已有的哪些概念/实体相关？
2. **增补**：有没有新信息可以补进已有的概念页或实体页？

**你的体验：** 就是在聊天。你不需要知道 wiki 在更新。聊完之后，wiki 自动多了几行 Evolution timeline、某个实体页多了一条 Mention、或者某个概念页的 Open Question 被回答了。

**实现方式：** Stop hook — 每次 Claude Code 对话结束时，自动判断"这次对话有没有值得沉淀的 context"，有就静默 ingest。

### Mode 2: 口述历史（主动提问式）

**触发者：Wiki（通过 Claude）**
**场景：** Wiki 检测到 context gap，主动向你提问。你像口述历史一样回答。

**问题来源（按优先级）：**

1. **概念页的 Open Questions** — 每个概念页底部都有 "Open Questions"，这些是 wiki 已经知道该问但还没答案的。
   - 例："你 2025 年 9 月蒸馏田渊栋时，是他的哪个特质让你决定要'明明白白的学'？"

2. **薄弱概念页** — confidence: low 或内容 < 100 字的概念页，说明数据不足。
   - 例："wiki 里关于你和父母关系的记录很少——你能讲讲你们的沟通模式是什么样的吗？"

3. **时间线空洞** — 某段时间没有任何记录，说明那段经历还没被表达。
   - 例："2025 年 10-11 月的记录比较少，那两个月你在做什么？"

4. **实体页的模糊关系** — wiki 知道某人对你重要，但不清楚为什么。
   - 例："你多次提到李春洋的 'Build Trust First'。你们是怎么认识的？什么时候开始觉得他重要？"

5. **跨源矛盾** — Notion 日记里的情绪和 Gemini 技术讨论里的方向不一致。
   - 例："2026 年 1 月你在 Notion 里写'焦虑到熬夜玩手机'，但同期 Gemini 里你在密集讨论 Flow Matching 数学推导。当时实际是什么状态？"

**你的体验：** Claude 问你一个精准的问题。你用最自然的方式回答——可以口语化、可以碎片化、可以带情绪。Claude 把你的回答 absorb 进 wiki。

**交互示例：**

```
Claude: wiki 里记录了你 2025 年 8-9 月密集研究 Sink/RoPE，并且在 9 月写下
       "卧槽太爽了，理解了其实一切 sink key 的特殊性都是 rope 之后才获得的"。
       这个发现当时是怎么来的？是在读论文时突然想到的，还是做实验时观察到的？

你: 是这样的，那天我在看 attention pattern 的可视化，然后突然意识到
   如果把 RoPE 去掉，sink 的行为完全不一样。然后我就设计了一个对照实验...
   （巴拉巴拉自然地讲）

Claude: [静默更新 concepts/sink与rope.md 的 Evolution 和 Key Insights]
       有意思。那你当时有没有想过，这个发现如果推广到 DiT 会怎样？
       （基于 wiki 里后续你确实尝试了 DiT 迁移的记录，追问细节）
```

## 实现设计

### `/wiki chat` — Mode 1

不需要新命令。在 CLAUDE.md 中加一条规则：

> 每次对话结束时（Stop hook），如果对话中包含个人经历、思考、情感、对人物的评价等 context 信息，自动提取并更新相关 wiki 页面。更新应该是静默的——不需要通知用户，不需要用户确认。

### `/wiki interview` — Mode 2

新命令。流程：

1. 扫描 wiki 概念页，收集：
   - 所有 Open Questions
   - confidence < medium 的页面
   - 时间线空洞
   - 实体页的模糊关系
2. 按优先级排序，选 top 3 问题
3. 以自然对话的方式提问（不是问卷，是聊天）
4. 用户回答后，absorb 进 wiki
5. 如果用户聊开了，跟着聊（Mode 1 和 Mode 2 自然融合）
6. 结束时 commit

### 每日推荐问题（可选）

Cron job 每天生成 1 个问题，存到 `wiki/interview/daily-question.md`。用户看到后可以在任何时候回答——甚至可以通过微信语音转文字回答。

## 设计原则

1. **零摩擦** — 你永远不需要"决定记录什么"。聊天就是记录，回答问题就是记录。
2. **精准提问** — 不是泛泛的"你有什么想分享的"，而是基于 wiki 的 gap 分析提出的具体问题。
3. **自然语言** — 你用最口语化的方式回答，LLM 负责结构化和编织。
4. **静默更新** — wiki 的更新不打断你的思路。
5. **越用越好** — 每次交互都让 wiki 更完整，wiki 更完整就能问出更精准的问题。

## 与现有系统的关系

```
现有:
  /wiki ingest  — 你主动喂数据（高摩擦）
  /wiki query   — 你主动问问题
  /wiki compile — 批量编译

新增:
  chat mode     — 你随便聊，context 自动流入（零摩擦）
  /wiki interview — wiki 主动问你，你口述回答（零摩擦）
```

核心转变：从"你记录自己"变成"wiki 理解你，然后来找你确认和补全"。
